# 文档敏感词批量清除工具

> michaelqiu 出品

一个纯本地运行的文档扫描与脱敏工具，支持 Word、Excel、PowerPoint 和常见文本文件。文件不会上传到服务器，网页端与命令行都可离线使用。

## 能做什么

- 批量扫描文件夹、磁盘或报告清单，定位文档中的密级标识、敏感词和个人信息。
- 按首行、尾行或全文清除命中内容，支持删除、智能打码和自定义替换。
- 直接处理 OOXML 文档，包括正文、页眉页脚、批注、修订、图表缓存、文档属性和内嵌 Office 文件。
- 预览命中位置，处理后复查残留，并导出 JSON、CSV 或 HTML 报告。
- 为批量结果提供筛选、连选、误报复核和人工复核清单。
- 导入 JSON 清单、通用检查报告的 HTML 表格或纯路径清单后继续处理。

## 快速开始

### Windows

1. 解压发布包。
2. 双击 `启动工具.exe`，或运行 `Start.bat`。
3. 浏览器打开 `http://127.0.0.1:8080/index.html`。

也可以直接用 Chrome 或 Edge 打开 `index.html`。

### Linux / UOS

```bash
bash Start.sh
```

启动脚本只监听 `127.0.0.1`，局域网中的其他设备无法访问本地服务。

## 新增能力速览

界面支持文件夹扫描、文件名关键字、区分大小写、扫描结果筛选、人工复核清单、批量删除和脱敏。主要按钮、标签和选项均带有悬停说明。

当前 `index.html` 的 149 处解释和由脚本动态生成的 15 处说明都带键盘焦点样式。默认词库扩到 38 词，`npm test` 一次跑完全部 10 套测试。

命令行提供以下参数：

- 扫描：`--dir`、`--drive`、`--depth`、`--limit`、`--ext`、`--all-ext`、`--docs-only`
- 筛选：`--words`、`--whole`、`--scope`、`--name-words`、`--name-mode`、`--case-sensitive`、`--exclude`、`--exclude-ctx`
- 报告：`--json`、`--report`、`--html`
- 处理：`--clean`、`--out`、`--root`、`--in-place`、`--action`、`--custom`、`--delete`、`--delete-dry-run`
- 选择结果：`--from-report`、`--pick`、`--pick-word`、`--pick-dir`、`--pick-list`
- 安全控制：`--authorized-root`、`--confirm-delete`、`--allow-network-paths`、`--confirm-network-paths`
- 其他：`--move-to`、`--move-dry-run`、`--shard`、`--concurrency`、`--max-file-mb`、`--no-skip-system`、`--verify`

## 按报告处理

报告属于外部输入。命令行会用 `--authorized-root` 限定报告可以触碰的目录：

```bash
node scan.mjs --from-report report.json \
  --authorized-root "D:\资料" \
  --out cleaned
```

就地脱敏：

```bash
node scan.mjs --from-report report.json \
  --authorized-root "D:\资料" \
  --in-place
```

删除默认只演练。确认清单无误后再显式加上确认开关：

```bash
node scan.mjs --from-report report.json \
  --authorized-root "D:\资料" \
  --delete --confirm-delete
```

网络路径默认拒绝。确需处理时，必须同时提供 `--allow-network-paths` 与 `--confirm-network-paths`。

## 支持的格式

- Word：`docx`、`docm`、`dotx`、`dotm`
- Excel：`xlsx`、`xlsm`、`xltx`、`xltm`
- PowerPoint：`pptx`、`pptm`、`potx`、`potm`、`ppsx`、`ppsm`
- PDF：`pdf`（正文解压 + 字形还原，只读检测；纯图片无文本层的扫描件标记为「扫描件」，需人工复核）
- 压缩包：`zip`、`jar`、`apk`、`epub` 等（解开逐条检索，只读检测）
- 文本：`txt`、`md`、`csv`、`tsv`、`json`、`xml`、`html`、`log`、`ini`、`yaml`、`sql` 及常见源码文件

旧版二进制 `doc`、`xls`、`ppt` 与 `pdf`、`rtf`、`zip` 支持**只读检测**（能检出敏感词，但不能原地清除）；需要清除时请先转存为受支持的 OOXML 格式。`rar`、`7z`、磁盘镜像等无法解包，只按文件名判定。扫描件 PDF 无可读文本层，不做 OCR、不猜内容，一律标记为「扫描件」转人工复核。

## 扫描覆盖与未检查清单

- 扫描结束会分别给出「遍历文件数 / 实际检查文件数 / 命中文件数 / 仅检测文件数 / 未检查文件数」，不再把「没扫到」当成「干净」。
- 未检查文件会按原因归类：格式不支持、超过大小上限、读取失败、文件名未匹配、达到文件数上限、目录无权限。
- 结果卡片下方可展开「未检查清单」核对路径样本，并可单独导出 CSV；CSV / JSON / HTML 报告也会带上未检查计数与原因。

## 命中位置溯源

- 每个命中都会按部件记账：`备注（ppt/notesSlides/notesSlide1.xml） × 2 处：机密`、`文档属性（docProps/core.xml） × 1 处：绝密`。
- 密级标识常写在备注页、图表、文档属性、形状名或内嵌对象里，正文翻不到——只报命中词会让「查出来了却找不到」。
- 覆盖 OOXML 全部文本部件、属性值、图表、批注、脚注尾注、自定义 XML、内嵌 Office 文档，以及 ZIP 目录里的条目名。
- 网页端在扫描结果表悬停命中词即可看到位置，预览面板在命中词徽章下方列出各部件明细；三种导出报告都带「命中位置」列。
- 命令行 `scan.mjs` 的 CSV 增加 `parts` 列，HTML 清单增加「命中位置」列，逐条命中日志新增「位置」行。

## 检出口径

外部保密检查软件按「文件名 + 解包后全文」检索，不会只看正文首尾行。本工具的检出与它对齐：

- **文件名也算命中**：名为「机密合同.docx」的文件即使正文干净也会被报出，位置标为「文件名」，只取文件名不含目录。
- **旧版 Office 两种字节对齐都查**：`doc` / `xls` / `ppt` 里的文本按 UTF-16 存放但不保证 2 字节对齐，错位命中会标「OLE错位」。
- **按文件头判断真实格式**：后缀写 `.doc` 而内容其实是 RTF（文件头为 `{\rtf1`）的情况很常见，这类文件的中文常以 `\'hh` 十六进制转义存放，按 OLE2 或 UTF-8 读取都看不到正文。现在先认文件头再选解析方式，命中位置标为「RTF」。
- **命名空间前缀写法也能读**：部分在线工具导出的表格写成 `<x:c><x:v>`，块正则按无前缀标签写死会整份漏检，现在按文本节点兜底。
- **PDF 正文也读**：自带 DEFLATE 解压与 `/ToUnicode` 字形还原，能读到压缩内容流、表单 XObject（页眉 / 水印常放在这里）里的文字；为两端对齐逐字定位的标题会把汉字之间的空白归一，避免「内 部」把词拆散。页面藏在 `/ObjStm` 对象流里也能展开；只设了权限密码的空口令加密（RC4 / AES-128）按标准安全处理器解开。扫描件（纯图片无文本层）显式打「扫描件」标签并在汇总里单列「扫描件 PDF 数」——不做 OCR、不猜内容，需人工复核或另存为文本格式；0 命中的扫描件也会进「未检查清单」和 HTML 清单的「扫描件 PDF」小节，不会因为查不到词就消失。损坏文件、AES-256 等其他读不到正文的同样降级为「仅文件名」，位置标注都会写清原因。
- **压缩包会解开查**：`zip` / `jar` / `apk` 等按「解包 + 逐条检索」处理，包里直接放的文档按各自格式解析，条目名也计入命中，位置标到包内路径。`rar` / `7z` 没有可用的解压实现，只查文件名并在报告里标明。
- **公文文号要求括号年份**：`国发〔2023〕5号` 这类完整形态才算文号；按裸词匹配会把「其中发明专利」「政府办公室」清成断句。
  用 `--words` 自己给的词不受此限制，要什么查什么。
- 清除后的自检同时复检输出文件名；正文清完但输出名仍含敏感词时会提示重命名（改名会影响引用，工具不代做）。

## 本地性与安全边界

- 网页资源没有外部依赖，文件处理在浏览器内完成。
- 启动脚本显式绑定回环地址 `127.0.0.1`。
- 报告派生路径会解析真实路径，并拒绝授权根之外的路径、路径前缀碰撞和符号链接越界。
- ZIP 解压、条目数量、内嵌文档深度、累计大小和解析时限均有上限。
- 扫描报告可能包含真实路径，处理完成后应妥善保存或删除。

安全问题请通过仓库的私下安全渠道报告，不要在公开 issue 中附带真实文档或检查报告。
